## 测试用例

### test_cases.json

包含40条精心设计的测试用例:
- **产品→开发**: 20条用例,涵盖各种产品需求场景
- **开发→产品**: 20条用例,涵盖各种技术方案场景

每条用例包含:
- `id`: 用例编号
- `content`: 待翻译的内容

## 测试脚本

### 1. pytest自动化测试 (test_translation_cases.py)

使用pytest框架的参数化测试,适合CI/CD集成。

#### 安装依赖
```bash
pip install pytest pytest-asyncio
```

#### 运行测试
```bash
# 运行所有测试
pytest tests/test_translation_cases.py -v

# 运行所有测试并显示详细输出
pytest tests/test_translation_cases.py -v -s

# 只运行产品→开发测试
pytest tests/test_translation_cases.py::TestProductToDev -v

# 只运行开发→产品测试
pytest tests/test_translation_cases.py::TestDevToProduct -v

# 运行流式输出测试
pytest tests/test_translation_cases.py::TestStreamingBehavior -v

# 运行边界情况测试
pytest tests/test_translation_cases.py::TestEdgeCases -v

# 生成HTML测试报告
pytest tests/test_translation_cases.py --html=report.html
```

#### 测试内容
- ✅ 翻译结果非空验证
- ✅ 翻译结果长度验证
- ✅ 关键词存在验证
- ✅ 流式输出增量性验证
- ✅ 边界情况测试(极短/极长/特殊字符)

### 2. 手动测试脚本 (manual_test.py)

交互式测试脚本,方便开发时手动验证。

#### 快速测试(前3个用例)
```bash
python tests/manual_test.py quick
```

#### 测试所有用例
```bash
python tests/manual_test.py all
```

#### 交互式测试
```bash
python tests/manual_test.py interactive
```

在交互模式下:
1. 选择翻译方向(1: 产品→开发, 2: 开发→产品)
2. 输入待翻译内容
3. 实时查看流式输出结果
4. 可以反复测试不同内容

## 测试用例示例

```
我们需要一个智能推荐功能,提升用户停留时长
```

**预期输出应包含**:


**预期输出应包含**:
- 用户体验提升(页面加载更快)

- 成本与收益(性能提升百分比)
- 可量化的业务指标
- 商业价值总结

## 质量标准

### 翻译质量评估标准

**产品→开发翻译应满足**:
1. 包含技术方案选型建议
2. 说明数据来源和处理方式
3. 给出性能和实时性要求
4. 评估开发工作量
5. 指出技术风险
6. 语言专业、结构清晰

**开发→产品翻译应满足**:
1. 用业务语言表达
2. 量化用户体验提升
3. 说明业务增长潜力
4. 分析成本与收益
5. 提供可量化指标
6. 避免技术术语

### 流式输出要求
- 首字响应 < 2秒
- 逐字逐句输出(非阻塞)
- chunk数量 > 10
- 无明显卡顿

## 常见问题

### Q1: 测试失败怎么办?
A: 检查以下几点:
1. QWEN_API_KEY是否正确配置
2. 网络连接是否正常
3. 通义千问API是否有速率限制
4. 查看日志文件(logs/app.log)

### Q2: 翻译结果不符合预期?
A: 可能的原因:
1. 提示词需要优化(修改app/prompts/)
2. AI模型版本不同
3. 输入内容过于模糊
4. 需要人工审核和调整

### Q3: 流式输出不流畅?
A: 检查:
1. ai_client.py中是否有`await asyncio.sleep(0)`
2. 网络延迟是否过高
3. 服务器性能是否足够
